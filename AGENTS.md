# AGENTS.md

## Project
`pomo` is a Go 1.25 terminal Pomodoro app. It uses Cobra for the CLI, Bubble Tea/Bubbles/Lipgloss for the TUI, Viper for YAML configuration, and SQLite (via `sqlx` + `modernc.org/sqlite`) for session history.

## Layout
- `pomo.go` — executable entry point.
- `cmd/` — Cobra commands and argument/flag parsing; starts Bubble Tea programs.
- `config/` — global configuration (`config.C`), defaults, config loading, schema, and embedded notification icon.
- `ui/` — timer state machine and rendering; `ui/stats/` and `ui/confirm/` are focused TUI components.
- `db/` — SQLite schema, connection setup, repository queries, and streak calculations.
- `actions/` — notifications and configured post-session commands.

## Commands
```sh
go fmt ./...
go build ./...
go vet ./...
go test ./...
go run .          # run the timer
DEBUG=1 go run .  # write Bubble Tea logs to debug.log
```
CI runs `go build -v ./...`, `go vet ./...`, and `go test ./...` with Go 1.25. Run all three checks after Go changes; format changed Go files first.

## Code and test conventions
- Follow idiomatic Go and `gofmt`; keep package responsibilities aligned with the layout above.
- Add tests beside implementation in `*_test.go`. Tests use `testify`; prefer table-driven cases for input variations. Use `require` for setup that must stop the test and `assert` for independent expectations.
- Bubble Tea state is intentionally split: `Model.Update` dispatches messages, while `*Model` handlers mutate state and return `tea.Cmd`. Preserve this pattern and model state transitions rather than performing blocking work in `Update`.
- Use `tea.Msg`/`tea.Cmd` for asynchronous UI work. Post-session actions run concurrently, and quit/start behavior deliberately coordinates their cancellation and wait group.
- Keep database access in `db.SessionRepo`; use the existing `DateFormat`, session types, and normalized daily-stat queries for stats features.

## Common pitfalls
- Configuration is process-global (`viper` and `config.C`). Config tests must reset both (`setupViper`) to avoid cross-test contamination.
- A user `pomo.yaml` in the current directory takes precedence over the per-user config. Changes to a config field normally require matching updates to `Config`/`DefaultConfig`, `config/schema.json`, the sample `pomo.yaml`, tests, and user-facing README documentation.
- CLI duration/flag parsing mutates the loaded global task configuration before `ui.NewModel`; do not treat these values as immutable defaults.
- `recordSession` guards against duplicate/near-zero records and handles short sessions specially. Keep that lifecycle behavior intact when changing timer transitions.
- The SQLite database is user state (`~/.local/state/pomo` on Linux/macOS); schema changes need an additive migration strategy and repository tests using in-memory SQLite.
- Releases package `pomo.yaml` and are generated by GoReleaser; keep Conventional Commit messages, especially `feat:` and `fix:`, so release changelog grouping stays correct.

## Scope
Do not modify generated binaries, `dist/`, `debug.log`, or local `*.db` files. Do not overwrite unrelated in-progress changes.
